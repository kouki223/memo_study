# 汎用AIにコア機能が食われる

## 自分のコアとは？

Moat層
生成AIプロダクトのMoat => 競争優位性
Moat1
- ワークフロー統合
- Difyのような内製化するローコードツール
Moat2 
- 品質保証
- エンプラ領域においては重要な事
- 秘伝のプロンプト・ガードレール
- 張るしネーション
- ファクトチェック
- 著作権保護
- この領域は徐々に喰われ始めている
Moat3
- 暗黙知の蓄積
- 組織固有のデータが貯まる
- 出力が組織に対してフィットしていく
- 意味のあるデータを取得するためのUXが必要になる(ポリシー的な問題も含めて)

Moatは階層構造になる
- 1 => 2 => 3

非構造化データを構造化して、トレーサビリティを担保する => 活用する事ができるようになる

- 例（Story Hub）
Moat1&2のプロダクトからMoat3へ
統合していたものを作る際の人間の思考や行動を構造化して、それを活用して、アウトプットを出す事ができるようにする

スコープ大 * 機会損失 小~中

ユーザーのメンタルモデルとプラダクトUXの乖離が大きくなる
営業 * CSから現状のセットで戦える事を確認している
↑
この情報から実行に進んだ

## 進むか止まるかを判断する事が出来るようにする

判断するべき事がある
- 機会損失*変更スコープ
- 機会損失 => 新規機能開発
- 変更スコープ => UIに閉じる or データモデルの変更が必要になる

## 戦略とプロダクトの実態をアラインさせる

エンジニアに必要な視座が今後、上がっていく事が必要になる
=> AIがコードを書く事や、様々な環境を繋げる事に対して責任を持ってくれるから

戦略とプロダクト構造の整合性を保つという事にCTOやVPoEのみの責任ではなくなる
=> 抽象的な道筋を立てる事ができるようにする

各種様々な戦略が存在する上でそれらを理解して応える
↑
全社戦略
中長期的な戦略など
例）マルテテナントの管理が必要になる可能性など
↑
この戦略とプロジェクトをアラインさせるという視点に立つ事をAIという開発基盤の上で行う事が出来れば少人数だとしても実現可能なものになる
